# تحلیل افزودن منبع نرخ «نوسان» (navasan.tech) + پیش‌فرض‌کردن آن

> تاریخ: ۱۴۰۵/۰۶/۲۱ — وضعیت: **پیاده‌سازی شد (v0.9.2)** — منبع «نوسان» اضافه و پیش‌فرض شد؛ زنجیرهٔ بازگشت
> (نوسان ← er-api ← سنا)، ذخیره/ماسک کلید، دکمهٔ تست اتصال و مستندات کامل پیاده و تست شدند (تست‌های `tests/test_navasan.py`).
> منبع بررسی: `app/rates.py`، `app/web.py` (نسخه 0.9.1) + تست زندهٔ سرویس نوسان.

---

## ۱) خلاصهٔ اجرایی

| # | مورد | نتیجه |
|---|---|---|
| 1 | آدرس رسمی API | `https://api.navasan.tech/latest/?api_key=KEY` (HTTPS هم کار می‌کند) |
| 2 | نیاز به کلید | **بله** — کلید رایگان از ربات تلگرام `@navasan_contact_bot`؛ بدون کلید پاسخ `api_key is missing` / `Invalid api_key` برمی‌گردد |
| 3 | واحد نرخ | **تومان** → باید ×۱۰ شود تا به «ریال» سیستم ما برسد (دقیقاً مثل منبع tgju) |
| 4 | شکل پاسخ | JSON با کلیدِ نماد: `{"usd_sell":{"value":"11270","change":-25,"timestamp":...,"date":"1398-06-20 19:12:30"}, ...}` — مقدار `value` **رشته (string)** است |
| 5 | پوشش ارزهای ما | USD/EUR/GBP/AED/TRY/CHF/CNY/RUB دارد؛ **IQD (دینار عراق) ندارد** |
| 6 | مزیت مهم | نرخ **خرید/فروش جدا** (`usd_sell`/`usd_buy`) و نرخ تهران/هرات/حواله — دقیقاً مناسب سیستم **چندنرخی** ما |
| 7 | محدودیت مهم | پلن رایگان فقط **۱۲۰ درخواست در ماه** (به‌روزرسانی هر ۲ ساعت) — با خودکارِ فعلی «هر ۳۰ دقیقه» سازگار نیست (به بخش ۵) |
| 8 | خروجی ویجت رایگان | `wp-navasan.php` فقط HTML جدول داخل JSONP برمی‌گرداند، نه JSON تمیز — **به‌عنوان API مناسب نیست** |

**جمع‌بندی:** افزودن نوسان به‌عنوان منبع چهارم ساده است (ساختارش شبیه tgju است)، اما «پیش‌فرض‌کردن» آن باید با **زنجیرهٔ بازگشت (fallback)** همراه شود، چون بدون کلیدِ معتبر از کار می‌افتد و پلن رایگان هم سقف ماهانهٔ پایینی دارد.

## ۲) شناخت منبع (آنچه تأیید شد)

### ۲٫۱) نقاط پایانی (endpoints)

| مسیر | توضیح | نیاز کلید |
|---|---|---|
| `GET /latest/?api_key=KEY` | آخرین نرخ لحظه‌ای همهٔ نمادها | بله |
| `GET /latest/?api_key=KEY&item=usd_sell` | فقط یک نماد (فیلتر برای صرفه‌جویی در سهمیه) | بله |
| `GET /dailyCurrency/?api_key=KEY&item=...&date=...` | همهٔ به‌روزرسانی‌های یک نماد در یک روز | بله |
| `GET /ohlcSearch/?api_key=KEY&item=...&start=...&end=...` | آرشیو OHLC روزانه | بله |
| `GET /usage/?api_key=KEY` | **میزان مصرف ماهانه/روزانه/ساعتی** (عالی برای مدیریت سهمیه) | بله |

### ۲٫۲) رفتار واقعی تست‌شده (live)

```
GET https://api.navasan.tech/latest/          → 401, body: "api_key is missing"      (متن ساده، نه JSON)
GET https://api.navasan.tech/latest/?api_key=test → 200, body: "Invalid api_key"     (متن ساده)
GET https://www.navasan.tech/wp-navasan.php?usd&eur  → JSONP شامل HTML جدول (نه دادهٔ تمیز)
```

> نکته: پاسخ خطا **JSON نیست**؛ fetcher باید `Content-Type`/بدنهٔ غیر-JSON را تحمل کند و پیام فارسی شفاف بدهد.

### ۲٫۳) نمادهای مهم برای ما (جدول راهنمای خودشان)

| نماد نوسان | معنی | نگاشت پیشنهادی به کد ما | rate_type پیشنهادی |
|---|---|---|---|
| `usd` | دلار آمریکا | `USD` | `market` |
| `usd_sell` / `usd_buy` | دلار تهران فروش / خرید | `USD` | `sell` / `buy` |
| `eur` | یورو | `EUR` | `market` |
| `gbp` | پوند | `GBP` | `market` |
| `aed` / `aed_sell` | درهم امارات | `AED` | `market`/`sell` |
| `try` | لیر ترکیه | `TRY` | `market` |
| `chf` | فرانک سوئیس | `CHF` | `market` |
| `cny` | یوان چین | `CNY` | `market` |
| `rub` | روبل روسیه | `RUB` | `market` |
| `cad`, `aud`, `jpy`, `sgd` … | سایر ارزها | (در صورت افزودن ارز به سیستم) | `market` |
| — | دینار عراق | **IQD وجود ندارد** | باید از منبع دیگر (er-api) بیاید |

## ۳) طرح یکپارچه‌سازی (نقشهٔ دقیق، برای وقتی گفتید «شروع کن»)

### ۳٫۱) `app/rates.py`

1. افزودن به `PROVIDERS`:
   ```python
   "navasan": {"name": "نوسان (navasan.tech)", "url": "https://api.navasan.tech/latest/",
               "has_irr": True, "needs_key": True, "desc": "نرخ لحظه‌ای بازار ایران (تومان)"},
   ```
2. نگاشت نمادها:
   ```python
   NAVASAN_MAP = {"usd": ("USD", "market"), "usd_sell": ("USD", "sell"),
                  "usd_buy": ("USD", "buy"), "eur": ("EUR", "market"),
                  "gbp": ("GBP", "market"), "aed": ("AED", "market"),
                  "try": ("TRY", "market"), "chf": ("CHF", "market"),
                  "cny": ("CNY", "market"), "rub": ("RUB", "market")}
   ```
3. تابع `fetch_navasan()`:
   - کلید را از `settings(rate_navasan_key)` یا env `SARRAFI_NAVASAN_KEY` بخواند.
   - اگر کلید نبود: `raise ValueError("کلید API نوسان تنظیم نشده — از ربات @navasan_contact_bot دریافت کنید")`.
   - GET `.../latest/?api_key=KEY`؛ اگر پاسخ JSON نبود (متن «Invalid api_key»)، خطای شفاف.
   - برای هر نماد: `value` رشته است → `int(round(float(v) * 10))` (**تومان → ریال**).
   - خروجی فعلاً مثل tgju: `{"IRR": 1, "USD": ..., "EUR": ...}` (مرحلهٔ اول فقط `market`).
4. ثبت در `FETCHERS`.

### ۳٫۲) `app/web.py`

- مسیر `/api/rates/fetch`: پیش‌فرض را به `navasan` ببریم ولی با fallback:
  ```python
  provider = d.get("provider") or self._get_setting(conn, "rate_source") or "navasan"
  ...
  # اگر navasan انتخاب شده ولی کلید/سهمیه درست نبود → fallback به er-api (اختیاری)
  ```
- `_rates_status`: پیش‌فرض `rate_source` → `navasan`.
- افزودن endpoint ذخیرهٔ کلید: در `POST /api/rates/settings` (یا مشابه) فیلد `navasan_key` را ذخیره و **در خروجی ماسک** کند.

### ۳٫۳) تنظیمات / UI (`app/static/js/app.js`)

- منبع «نوسان» خودکار در لیست `providers` می‌آید (چون از `rates.PROVIDERS` خوانده می‌شود).
- افزودن فیلد «کلید API نوسان» در کارت «نرخ ارز آنلاین» + دکمهٔ «تست اتصال».

### ۳٫۴) نسخه

- پیشنهاد: **0.9.2** (افزودن منبع، بدون شکستن ساختار). همگام‌سازی نسخه در `web.py` + `tests/test_v04.py` + `tests/test_v06.py`.

## ۴) نکات و ریسک‌ها (باید در پیاده‌سازی لحاظ شود)

1. **تومان → ریال ×۱۰** — فراموش‌کردن این تبدیل، نرخ را ۱۰ برابر غلط ذخیره می‌کند.
2. **`value` رشته است** نه عدد — `float()` الزامی است (مثل `"11270"`).
3. **پاسخ خطا JSON نیست** — `json.loads` کرش می‌کند؛ باید try/except و پیام فارسی.
4. **IQD ندارد** — دینار عراق فقط از er-api می‌آید؛ با fallback حل می‌شود.
5. **سهمیهٔ ۱۲۰/ماه در پلن رایگان** — مهم‌ترین ریسک:
   - خودکار فعلی «هر ۳۰ دقیقه» = ۴۸ درخواست/روز = ~۱۴۴۰/ماه ≫ ۱۲۰.
   - راهکار: وقتی منبع نوسانِ رایگان است، بازهٔ خودکار را به «هر ۲ ساعت» محدود کنیم + `item=` بفرستیم + از `usage/` سهمیه را بخوانیم و قبل از اتمام متوقف شویم + در پایان fallback به er-api.
6. **کلید باید امن بماند** — در env یا ستون تنظیمات؛ هرگز در لاگ/بکاپِ متنی/پاسخ API لو نرود (ماسک در UI).
7. **قیمت‌های صفحهٔ نمایشی نوسان قدیمی/نمونه‌اند** — به جدول دموی سایت اتکا نکنید؛ فقط API ملاک است.
8. **ابهام در نماد `usd` در برابر `usd_sell`** — برای نرخ «بازار» بهتر است از `usd` (میانگین) یا `usd_sell` استفاده شود؛ باید در پیاده‌سازی صریح تصمیم بگیریم و در doc بنویسیم.

## ۵) چطور «پیش‌فرض» کنیم بدون اینکه سیستم بشکند؟

پیشنهاد من (به‌عنوان بهبود): **پیش‌فرض با زنجیرهٔ بازگشت**، نه پیش‌فرض سخت.

ترتیب پیشنهادی هنگام دریافت نرخ:
1. `navasan` (اگر کلید تنظیم شده و سهمیه باقی است)
2. `er-api` (رایگان، بدون کلید، شامل IQD)
3. `tgju` (سنا)

دلیل: اگر پیش‌فرض سخت روی نوسان باشد و کاربر کلید نداشته باشد (یا سهمیه تمام شود)، دکمهٔ «دریافت نرخ لحظه‌ای» همیشه خطا می‌دهد و تجربهٔ کاربر خراب می‌شود. با fallback، «نوسان اگر بشود، وگرنه er-api» رفتار پیش‌فرض می‌شود.

## ۶) پیشنهادات بهبود (خارج از خودِ نوسان)

1. **زنجیرهٔ بازگشت چندمنبعی** (بالا) + ذخیرهٔ «آخرین منبع موفق» تا دفعهٔ بعد همان را اول امتحان کند.
2. **مدیریت سهمیه**: نمایش «مصرف این ماه» از `usage/` در تنظیمات + توقف خودکار قبل از اتمام سهمیه.
3. **نرخ خرید/فروش واقعی**: از `usd_sell`/`usd_buy` استفاده کنیم تا فرم خرید/فروش به‌جای یک نرخ بازار، bid/ask واقعی بگیرد (سیستم چندنرخی ما همین را می‌خواهد — `rate_type` آماده است).
4. **نرخ به تفکیک ارز**: بعضی ارزها (IQD) فقط در er-api هست؛ اجازه دهیم هر ارز منبع دلخواه داشته باشد یا در یک fetch، «ادغام» شود (navasan برای ارزهای موجود + er-api فقط برای IQD).
5. **تست اتصال**: دکمهٔ «تست کلید» کنار فیلد کلید نوسان.
6. **کش و فاصلهٔ حداقلی**: جلوگیری از فراخوانی مکرر پشت‌سرهم (rate-limit سمت خودمان + min-interval بین دو fetch).
7. **لاگ/نمایش بهتر**: در «آخرین دریافت» علاوه بر منبع، «چرا fallback شد» (کلید نبود/سهمیه/خطا) نمایش داده شود.
8. **HTTPS اجباری + timeout و retry** برای همهٔ منابع (نوسان http هم دارد؛ https تست شد و کار می‌کند).
9. **هشدار تغییر شدید نرخ**: اگر نرخ جدید با قبلی بیش از X٪ فاصله داشت، قبل از ذخیره تأیید/هشدار بدهد (جلوگیری از نرخ اشتباه ناشی از واحد تومان/ریال یا خطای منبع).
10. **آرشیو نوسان** (`ohlcSearch`) برای رسم نمودار تاریخی ارز در آینده.

## ۸) جمع‌بندی یک‌خطی

نوسان منبعِ ایرانیِ تمیز و مناسب است و ساختارش شبیه tgju (تومانی، JSON) است؛ تنها پیش‌نیازش **کلید API** است و سقف پلن رایگان پایین است، بنابراین پیش‌فرض‌کردن آن باید به‌صورت «نوسان ← er-api ← tgju» با مدیریت سهمیه انجام شود.
